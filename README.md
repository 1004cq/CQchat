# CQchat

附近设备之间的加密消息工具：无账号、无服务器、不依赖互联网。  
蓝牙发现与小消息；同一热点/局域网传较大加密媒体。

**不是**「杀进程后仍持续在线的 Mesh 基础设施」，也 **不是** 隐身通信应用。

iOS 与 Android **必须** 使用同一套二进制协议（见下方规范）。不要各写各的，不要复制 bitchat 代码。

## 第一版承诺（附近模式开启时）

- 发现附近设备（临时标识）
- 公频文字（签名，UI 标「公开消息」）
- 一对一私聊文字（Noise XX）
- 扫码核对手动验证身份（「已验证」/「未验证」）
- 短暂离开或断线：消息进队列，路径恢复后按规范重试
- 同一 Wi‑Fi/热点：较大加密媒体优先 TCP；失败可用同一 `msg_id` 回退 BLE（尺寸允许时）

系统限制：iOS 后台会合并/降频蓝牙任务，仍可能被系统杀掉；Android 后台依赖前台服务与权限。产品定义是：**用户开启附近模式后尽量维持；系统允许时后台恢复**——不承诺杀进程后仍转发或收消息。

## 第一版不承诺（后续）

长期后台 Mesh 中继、跨多跳大文件、杀进程后必达、无感知持续广播、复杂群组加密、多设备同步、Double Ratchet、已读回执。

## 隐私怎么理解

| 场景 | 附近设备可能观察到 | 用户应知道 |
|---|---|---|
| 仅发现 | 临时 ID + 协议版本 | 标识会轮换；无长期公钥/昵称进广播 |
| 公频 | 明文+签名 | 公开消息，非私密 |
| 私聊密文 | 密文与元数据图样 | 正文不可读（无会话密钥时） |
| 扫码验证后 | 可识别的长期身份关系 | **主动选择**绑定「已验证」 |

「公频不好追踪」≠「身份永不可识别」。未验证用短期标识；扫码后明确建立可识别关系。

## 怎么传

| 方式 | 用法 | 适合 |
|---|---|---|
| 蓝牙 | 发现、握手、文字、短语音 | 近距离；可多跳（后续阶段加固） |
| Wi‑Fi 热点/局域网 | mDNS 发现，TCP 只送已加密信封 | 图、语音、大包 |

大包优先 Wi‑Fi；失败回退 BLE 时 **同一 `msg_id`**，不重新握手。

## 身份与加密（三种概念）

1. **长期身份**：Ed25519（指纹二维码、公频签名）
2. **会话协商**：X25519（Noise 静态）
3. **会话消息密钥**：Noise 派生（ChaCha20-Poly1305）

首次本地生成 `identity_seed`，放 Keychain / Keystore。私聊 Noise XX；公频签名不加密。活会话有会话级前向安全；不把离线排队宣传成同等前向保密。

## 平台代码

- iOS：[`ios/`](ios/) · SwiftUI · CoreBluetooth · Keychain
- Android：[`android/`](android/) · Kotlin · BLE · Keystore · 前台服务（扫描常需定位权限）

## 通知

仅本地通知。杀进程、出范围不弹窗。附近人发现通知有冷却。

## 明确不做

账号、服务器、离线推送、实时通话、Nostr、好友系统、朋友圈。

## 和 imimchat 的区别

imimchat：账号、服务器、推送、通话。  
CQchat：附近、断网、加密、可当面核对。
