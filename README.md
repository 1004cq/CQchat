# CQchat

离线加密聊天。用蓝牙或 WiFi 热点，不用网，不要账号，不要服务器。

Offline encrypted chat over Bluetooth mesh and WiFi hotspot.

iOS 和 Android 必须用同一套协议。不能各写各的。

## 要求

给附近的人用。关网能聊，私聊端到端，比 bitchat 好用：能传图和语音消息，身份能当面核对，消息少丢，广播不好追踪。

不做：账号、服务器、离线推送、实时通话、Nostr、好友系统、朋友圈。

## 怎么传

| 方式 | 用法 | 适合 | 人数 |
|---|---|---|---|
| 蓝牙 Mesh | 自动发现，多跳中继 | 文字、短语音、发现 | 同一区域几十人可用 |
| WiFi 热点 / 同一局域网 | 一台开热点，或已在同一网 | 图、语音、大文件 | 一台手机热点约 10 人 |

优先蓝牙。热点或局域网可用时，大包走 WiFi。失败立刻退回蓝牙，同一个 `msg_id` 重发。

人多能传远，靠的是中间有更多手机转发，不是某一台手机性能强。空地里几个人还是传不远。

## 协议（两端共用）

自定义二进制包，不走 JSON。

| 字段 | 说明 |
|---|---|
| version | 协议版本 |
| type | 广播 / 私聊 / 确认 / 同步 / 媒体 / 握手 |
| sender | 临时标识或指纹 |
| msg_id | 去重 |
| ttl | 起始 7，每跳减 1 |
| payload | 密文、签名广播或握手数据 |

超过 MTU 分片，接收端按 `msg_id` 拼回。加密在会话层做完，传输层只搬密文。

## 身份

首次启动本地生成密钥对，不注册、不上传。

- 长期身份：X25519，放 Keychain / Keystore
- 昵称：可改，不参与认证
- 对方识别：公钥指纹，二维码当面核对
- 未扫过标「未验证」，扫过标「已验证」

## 加密

私聊：Noise XX（X25519 + ChaCha20-Poly1305）。

- 活会话有前向安全
- 每条消息带 `msg_id` 和递增 nonce
- 蓝牙和热点用同一会话密钥，不重新握手
- 公频：Ed25519 签名，不加密
- 第一期不上 Double Ratchet

## 防扫描

- 广播标识每几分钟轮换
- 发现包只放临时标识和版本
- 拒绝旧 nonce 和重复 `msg_id`
- mDNS 不放身份，TCP 只送密文
- 发包加随机延迟，密集时少跳

杀进程后仍可能被扫到有设备，不承诺隐身。

## 图片与语音

先压缩再加密再发。

- 图：长边约 1280，质量约 0.7，带小缩略图
- 语音：Opus
- 压完 < 100 KB 且只有蓝牙：分片发
- 更大且热点可用：TCP 发
- 否则进队列，界面显示等待，不假装已发出

## 平台

- iOS：Swift / SwiftUI，CoreBluetooth，Keychain。后台扫描和广播有限制 → [`ios/`](ios/)
- Android：Kotlin，BLE，Keystore。扫蓝牙通常要定位权限，后台用前台服务 → [`android/`](android/)
- 两端协议、密钥、包格式必须一致，才能互聊
- **二进制协议权威说明**（字段、端序、Noise、分片、媒体）：[`docs/PROTOCOL.md`](docs/PROTOCOL.md)
- 共享测试向量：[`shared/test-vectors/v1.json`](shared/test-vectors/v1.json)

## 蓝牙

- 每台同时 central 和 peripheral
- TTL 起始 7，去重 LRU 约 5 分钟
- 密集时降低跳数
- 直连约 10–50 米

## 热点

- mDNS 找本地 IP，TCP 送已加密信封
- 不做多跳
- 失败退回蓝牙

## 通知

只有本地通知。App 还在后台且蓝牙能扫到时才提醒。杀进程、出范围不弹窗。附近人通知做冷却。

## 第一期

- 本地密钥
- 蓝牙发现（标识轮换）
- 公频 + Noise 私聊
- 二维码核对
- 图和短语音（压缩、分片或排队）
- 本地通知

## 和 imimchat 的区别

imimchat 有账号、服务器、推送和通话。CQchat 只做附近、断网、加密。
